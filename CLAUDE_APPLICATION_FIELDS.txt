Tell us about the project's reach and impact

I'm building official-gisto-AI-assistant — a local-first AI assistant framework with memory, autonomous topic threading, toggleable capability modules (personal and agency), and integration adapters for Discord, Slack, Google Workspace, and Composio. The assistant has a defined persona, a system prompt that governs how it responds, and a permission system that gates what it can actually do.

The project sits in the gap between "chat with an AI in a web page" and "give an agent broad access to your machine and hope for the best." It's built so one person can run their own assistant locally or connect it to the surfaces they actually use — Discord, Slack, Google — without depending on a hosted platform and without handing their keys to one.

Under the hood, the framework has:
- A persistent per-user memory store (facts, preferences, history, active projects) that loads before acting and updates as it goes, survives restarts, and never stores your keys or tokens.
- Autonomous topic threading — conversations are organized into threads automatically, no manual "new chat" needed, with manual rename/merge/split as fallback.
- Toggleable modules: personal (assistant capabilities) and agency (lead finding, site building, outreach, client comms, project tracking). Agency includes everything in personal and adds the agency engine on top.
- Integration adapters for Discord, Slack, Google, and Composio — each optional, each needs your own keys, nothing wired by default.
- A defined persona and system prompt that governs how the assistant responds.
- A CLI entry point (`python -m gisto run|onboard|status`).
- An orchestrator with self-healing error containment — catches, logs, and recovers in-character, never crashes, never silent.

The project is young but real. The core framework is in place: the permission system with four levels (VIEW, ASSIST, CONTROL, FULL_ACCESS) and a real enforcement gate; the agent engine with memory, persona, and an operation registry; real PC control operations with implementations (system info, process list, file read/write/move/delete, process kill, command execution, application launch, browser navigation); the Discord bot wiring with persona, memory, threading, and onboarding; the CLI; the config system with env var overrides; and a master build prompt (CLAUDE.md) that defines the full scope.

Some pieces are still being finished — the full backend API endpoints, the web UI, the Discord bot integration, real detection rules for the threat engine, and the desktop app as a published product. The project is not a toy or a prompt doc: it has a real permission model, a real operation registry, a real memory layer, real integrations, a real Discord bot, and a defined persona that governs how the assistant responds.

The gap it fills is practical rather than theoretical: a personal assistant framework that is honest about control, honest about memory, and honest about what it can and cannot do — built so one person can run their own assistant on their own machine without turning it into a cloud service or giving an untrusted agent unrestricted access.
